## 第 3 页：研究背景

### PPT 核心文字

**为什么需要课堂专注度分析？**

传统课堂专注度评价主要依赖：

- 教师人工观察；
- 课后问卷；
- 少量课堂抽样记录。

存在的问题：

- 主观性较强；
- 无法持续记录整个课堂；
- 难以量化不同时间段的专注度变化；
- 课后缺少可追溯的历史数据；
- 难以支撑长期教学分析。

### 建议配图

使用一个简单流程图：

```text
传统课堂
教师观察 → 主观判断 → 课后总结

智能分析课堂
课堂视频 → AI行为识别 → 专注度计算 → 数据分析 → 教学反馈
```

### 讲解重点

不要把课题说成“监控学生”。更合适的表述是：

> 系统的目标是辅助教师进行课堂状态分析，通过量化的行为数据和趋势数据为教学调整提供参考，而不是替代教师对学生的综合评价。

## 第 5 页：研究现状

参考示例 PPT 的“系统对比”思路，但本课题不要虚构具体商业系统数据。

### 可以从三个方向比较

| 方向 | 常见方案 | 存在问题 |
|---|---|---|
| 人工评价 | 教师观察、问卷 | 主观性强、数据不连续 |
| 传统计算机视觉 | 手工特征、简单分类 | 对复杂课堂环境适应性有限 |
| 深度学习视觉分析 | YOLO 等目标检测模型 | 对数据集、遮挡、光照和模型泛化能力要求较高 |

### 当前研究需要解决的问题

1. 学生目标存在遮挡；
2. 课堂光照变化；
3. 不同行为之间存在视觉相似性；
4. 检测结果需要进一步转换为专注度指标；
5. 模型结果需要进入 Web 系统进行长期存储和分析。

### 答辩时的关键句

> 现有研究已经证明深度学习可以用于课堂行为分析，但从“检测模型”到“可使用的课堂专注度分析系统”仍需要解决算法评价、数据存储、Web 服务和可视化等工程问题，因此本课题重点研究模型与 Web 系统的结合。

## 第 10 页：专注度评价算法【重点页】

### 核心公式

```text
             Σ(Nᵢ × Wᵢ)
A = ───────────────────── × 100%
                ΣNᵢ
```

其中：

- `Nᵢ`：第 i 类行为人数；
- `Wᵢ`：第 i 类行为专注度权重；
- `A`：课堂专注度。

### 当前初始权重

| 行为 | 权重 |
|---|---:|
| 举手 | 1.0 |
| 阅读 | 1.0 |
| 写作 | 1.0 |
| 使用手机 | 0.0 |
| 低头 | 0.3 |
| 靠/趴在桌上 | 0.2 |

### 专注度等级

- ≥90%：非常专注
- 80%～90%：比较专注
- 70%～80%：中等水平
- 60%～70%：偏低
- <60%：不专注

### 必须主动说明

> 当前权重属于系统设计的初始参数，不直接宣称为通用标准。后续需要通过典型课堂样本、权重对比实验或人工评价进行验证。

### 这一页很可能被问

**问：为什么手机是 0，低头是 0.3？**

建议回答：

> 这些权重是基于课堂行为对专注程度的相对影响进行的初始建模。使用手机通常与当前学习任务关联性较低，因此设置为较低权重；低头可能存在阅读、思考等情况，因此不能简单视为完全不专注，所以设置为非零权重。后续会通过实验进一步验证和调整。

# 五、老师高概率提问及建议回答

## Q1：为什么选择 YOLOv8？

**建议回答：**

YOLOv8 属于典型的一阶段目标检测模型，推理速度较快，适合课堂视频中的多目标行为检测。同时项目原始基础已经存在 YOLOv8 课堂行为检测模型，因此可以在保留已有模型成果的基础上，将重点放在 Web 系统重构和专注度分析功能上。

---

## Q2：YOLOv8 检测的是学生还是专注度？

**建议回答：**

YOLOv8 主要负责识别课堂行为类别和目标位置，并不直接输出专注度。系统在检测结果基础上进行行为统计，再利用行为权重计算课堂专注度，因此检测层和评价层是分开的。

---

## Q3：专注度权重为什么这样设置？

**建议回答：**

当前权重是系统设计的初始方案，是根据不同课堂行为与学习状态的关联程度进行设置的，并不是通用标准。后续会通过不同权重方案对比和人工评价结果进行验证，再确定更合理的参数。

---

## Q4：为什么使用 FastAPI？

**建议回答：**

FastAPI 基于 Python，适合与 YOLOv8、OpenCV 等 AI 和计算机视觉工具结合，同时支持异步请求和 WebSocket，可以满足图片检测、视频任务和实时课堂检测等需求。相比原项目 PyQt5 桌面程序，FastAPI 更适合构建浏览器访问的 Web 系统。

---

## Q5：为什么选择 MySQL？

**建议回答：**

系统需要保存用户、课程、课堂、行为检测和专注度等结构化业务数据，数据之间具有明确的关联关系，因此采用关系型数据库。MySQL 成熟、稳定，并且与 SQLAlchemy ORM 集成方便，能够满足毕业设计的数据存储需求。

---

## Q6：系统如何保证不同教师之间的数据隔离？

**建议回答：**

系统通过 JWT 认证识别当前用户，在课程、课堂、检测和报告接口中进一步检查资源所属教师。管理员拥有全局管理权限，普通教师只能访问自己创建或负责的课程和课堂，后端权限检查是最终控制手段，而不是只依赖前端隐藏菜单。

---

## Q7：实时检测为什么使用 WebSocket？

**建议回答：**

实时课堂需要持续传输图像帧和检测结果，如果全部采用普通 HTTP 请求，会产生较多请求开销。WebSocket 建立长连接后可以持续双向传输数据，更适合实时检测场景。

---

## Q8：模型识别错误怎么办？

**建议回答：**

系统通过置信度阈值过滤低可信度检测结果，并通过 Precision、Recall、mAP、F1 和混淆矩阵分析模型效果。对于遮挡、光照和相似行为造成的误检漏检，后续可以通过补充数据集、数据增强、调整训练参数和优化模型进行改进。

---

## Q9：学生低头一定是不专注吗？

**建议回答：**

不一定。因此系统没有把“低头”直接定义为完全不专注，而是设置较低但非零的权重。这也是为什么专注度模型需要实验验证，不能简单地把行为类别与主观评价完全等同。

---

## Q10：你的创新点是什么？

**建议回答：**

本课题的重点不是提出新的目标检测网络，而是将已有 YOLOv8 课堂行为识别能力与 FastAPI Web 服务、专注度评价、MySQL 数据管理和实时 WebSocket 检测结合，形成一个完整的课堂专注度分析系统。同时通过行为权重和历史时序数据，将单帧检测结果进一步转化为可分析的课堂指标。
