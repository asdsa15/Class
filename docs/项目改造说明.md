## 五、与原报告的差异说明（重要）

1. **模型文件纠正**：报告第 3.1 节认为 `models/best.pt` 是课堂行为检测模型。
   实际检查权重元数据后发现，`models/best.pt` 的类别是
   `crazing / inclusion / patches / pitted_surface / rolled-in_scale / scratches`，
   属于**钢铁表面缺陷检测模型**（原项目作者的另一个课题），
   真正包含 6 类课堂行为的权重是 `runs/v8-4-pose-all2/weights/best.pt`。
   本系统已把正确的权重复制为 `models/classroom_behavior.pt`，
   并在 `config.py` 中配置了备用权重路径，避免加载到错误模型。

2. **数据库最终方案**：系统统一使用 **MySQL 8.0 的 `class_detection` 库**，
   表结构由项目根目录的 `class_detection.sql` 创建（5 张表 + 外键 + 索引），
   与 `database/models.py` 的 ORM 模型一一对应。
   数据库地址与密码不写进 `config.py`，全部通过 `.env` 配置（`.env` 已加入 `.gitignore`）；
   `CLASSROOM_SQLITE_FALLBACK` 默认为 `0`，MySQL 不可用时系统会直接报错并给出配置提示，
   不会静默切换到 SQLite（仅本机临时无 MySQL 时才手动改为 `1`）。
   旧的 SQLite 文件已备份为 `classroom_attention.db.bak`，不再参与运行。

3. **课程表增加 `class_name` 字段**：报告 17.2 节的 course 表未包含班级，
   但 24 节的课堂报告示例需要显示「班级」信息，因此补充了该字段。

4. **密码哈希实现方式**：报告第 13 节建议使用 passlib。
   考虑到 passlib 在高版本 Python 上存在兼容性问题，
   本系统使用标准库 hashlib 实现 **PBKDF2-SHA256**（算法与 passlib 的
   `pbkdf2_sha256` 方案一致），JWT 仍按报告建议使用 python-jose。

5. **视频检测任务存储**：视频检测任务进度保存在内存任务表中（保留最近 30 条），
   检测产生的行为数据与专注度数据仍写入数据库，因此历史统计不受影响。

6. **实时检测的三源设计**：报告只提到「摄像头」，
   实际实现同时支持**浏览器摄像头**、**服务器本机摄像头**与**本地视频文件**，
   便于在无摄像头的机房环境中演示实时课堂功能。

## 八、前端界面设计说明

### 8.1 设计目标

界面按「教务管理系统」的常规形态设计，而不是常见的模板化「数据大屏 / 落地页」风格：

* 整体浅色（页面底色 #f0f2f5，内容面板白色），不使用渐变、发光、悬浮阴影等装饰效果；
* 所有界面文字使用中文，不使用英文字母副标题、装饰性英文标签；
* 圆角统一 4px，分隔以 1px 实线为主，信息密度接近常规管理系统；
* 颜色仅用于表达状态（正常 / 进行中 / 异常）与图表分类，不用于装饰；
* 图表为原生 Canvas 手写实现，采用浅灰网格、细线条、平铺色块。

安全补充（对应报告第 19 节）：

* 登录失败次数限制（默认连续 5 次失败锁定 5 分钟，返回 429）；
