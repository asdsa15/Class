# 4. 优先级最高的两个功能优化

## 4.1 登录页面增加“记住密码”

### 当前问题

当前 `templates/login.html` 只有：

- 用户名；
- 密码；
- 登录按钮。

`static/js/login.js` 登录时只向 `/api/auth/login` 提交用户名和密码，没有“记住密码”的状态处理。

后端登录接口当前已经使用 HttpOnly Cookie 保存 JWT，因此这里的“记住密码”不应该直接把真实密码写入 Cookie、localStorage 或 sessionStorage。

### 推荐设计

采用更安全的“**记住账号 + 记住登录状态**”方案：

```text
□ 记住密码
```

用户勾选后：

1. 前端保存用户名；
2. 前端不保存明文密码；
3. 登录成功后延长认证 Cookie 有效期；
4. 未勾选时使用普通会话/较短有效期；
5. 退出登录时清理登录状态。

### 建议修改文件

```text
templates/login.html
static/js/login.js
schemas/user.py
routers/auth.py
config.py
```

### 推荐请求结构

将：

```json
{
  "username": "admin",
  "password": "******"
}
```

扩展为：

```json
{
  "username": "admin",
  "password": "******",
  "remember_me": true
}
```

### 后端处理建议

在 `LoginRequest` 增加：

```python
remember_me: bool = False
```

登录接口根据 `remember_me` 设置 Cookie：

```text
未勾选：会话 Cookie / 较短有效期
勾选：持久 Cookie / 较长有效期
```

Cookie 仍然应该保持：

- `HttpOnly=True`
- `SameSite=Lax`
- 生产环境 HTTPS 下启用 `Secure=True`

### 重要安全说明

**不建议按照“记住密码”的字面含义把密码保存到浏览器。**

毕业设计中可以将界面名称保留为“记住密码”，但论文实现说明应写成“记住登录状态/记住账号”，避免产生明文密码存储的安全问题。

当前系统虽然已经具备用户表和角色字段，但从毕业设计完整性来看仍建议增加以下功能。

## 6.1 修改用户信息

建议增加：

```text
PUT /api/auth/users/{user_id}
```

支持管理员修改：

- 角色；

## 6.2 重置用户密码

建议管理员能够执行：

```text
重置密码
```

但不能直接查看用户原密码。

## 6.3 用户状态

当前 `user` 表建议增加：

```text
status
```

例如：

```text
1 = 正常
0 = 禁用
```

这样管理员可以禁用账号，而不是必须删除账号。

## 6.4 防止删除关联数据

当前课程通过 `teacher_id` 与用户存在关联。

管理员删除教师前，应检查：

- 是否拥有课程；
- 是否存在课堂记录；
- 是否允许转移课程；
- 是否允许删除。

推荐毕业设计方案：

> 禁用教师账号，而不是直接删除教师。

这样可以保持历史课堂数据完整。

# 8. 专注度算法是当前最需要论文验证的部分

开题报告明确提出需要解决“专注度评分规则的合理性”问题，并指出模型训练数据量、遮挡、光照和泛化能力可能影响效果。fileciteturn0file0L70-L88

当前系统采用行为权重计算专注度：

```text
A = Σ(N_i × W_i) / Σ(N_i) × 100%
```

当前设计的核心问题不是代码能否运行，而是：

> 为什么举手、阅读、写作属于高专注？
> 为什么低头、趴桌、玩手机属于低专注？
> 为什么权重分别设置为 1.0、0.3、0.2、0？

## 必须优化

论文中不能只写：

> “设置权重后计算专注度。”

建议增加一组实验：

| 实验 | 内容 |
|---|---|
| 实验 1 | 使用原始权重计算结果 |
| 实验 2 | 调整低头权重 |
| 实验 3 | 调整趴桌权重 |
| 实验 4 | 不同课堂样本对比 |
| 实验 5 | 人工评价与系统评分对比 |

最终说明当前权重为什么作为实验方案采用。

开题报告本身也已经明确指出，权重需要通过实验或专家意见进行说明和验证，而不能直接视为通用标准。

# 10. 建议增加“检测结果 ≠ 专注度”的论文论证

当前代码已经将：

```text
detection/detector.py
       ↓
detection/behavior.py
       ↓
detection/attention.py
```

进行分层，这是正确设计。

论文中应该明确：

> YOLOv8 输出的是课堂行为检测结果，而不是直接输出“专注度”。系统首先统计行为类别及人数，再根据行为权重计算课堂专注度。

这样可以避免论文在算法逻辑上出现“YOLOv8 直接识别专注度”的表述错误。

推荐论文流程图：

```text
输入课堂视频
      ↓
视频帧提取
      ↓
YOLOv8 行为检测
      ↓
学生行为类别识别
      ↓
行为人数统计
      ↓
行为置信度过滤
      ↓
专注度权重映射
      ↓
专注度计算
      ↓
时序数据存储
      ↓
可视化 / 报告
```
