# 识别类别调整方案（方案2）：重新训练模型

> 目标：把当前 **6 类**识别体系调整为更贴合教学语义的类别体系（合并「阅读」「写作」为「专注学习行为」，并对「靠在桌上」的判定做优化）。
> 本文档说明**原理、可行性、完整实施步骤与风险控制**，供后续独立实施。

---

## 一、先厘清基本事实

在动手之前，必须明确三件事，否则容易走错方向。

### 1.1 当前识别的 6 个类别

| 编号 | 英文名 | 中文名 | 训练集实例数 | 占总量 |
|---|---|---|---|---|
| 0 | hand-raising | 举手 | 1552 | 6.3% |
| 1 | reading | 阅读 | 10067 | 40.5% |
| 2 | writing | 写作 | 3746 | 15.1% |
| 3 | using phone | 使用手机 | 7400 | 29.8% |
| 4 | bowing the head | 低头 | 979 | 3.9% |
| 5 | leaning over the table | 靠在桌上 | 1085 | 4.4% |
| | **合计** | | **24829** | 100% |

数据集划分：训练 1422 张 / 验证 203 张 / 测试 407 张，标注为 YOLO 标准 txt 格式（`类别号 x_center y_center w h`，均为归一化值）。

### 1.2 项目里**没有**「听课」这一类

这是最关键的一点。**「听课」不在模型的 6 个输出类别中**，它只出现在测试视频的原字幕水印里（那段视频截取自网络课堂录像，画面本身带有「听课网」字样）。模型的 `nc: 6` 与 `names` 列表里都没有它。

因此「增加听课类别」不是改文案的问题，而是**数据集里根本没有这类标注**——没有标注就无法训练。如果确实要识别「听讲」状态，必须先重新标注数据。

### 1.3 合并类别的两种路线

| 路线 | 做法 | 代价 | 适用场景 |
|---|---|---|---|
| **A. 逻辑合并（不重训）** | 模型仍输出 6 类，在统计层把 reading + writing 归入「专注学习」，报告中分组合并展示 | 极低，改 1~2 个文件 | 只是想在界面上看到合并后的结果 |
| **B. 标签合并 + 重训** | 修改标注文件把类别 1、2 合并为一类，重新训练 | 中，需数小时训练 | 希望模型只学 5 个类别，结构更简洁 |

本文档讲的是**路线 B**（你要求的方案2）。

## 二、类别体系设计（决定 `nc` 的值）

在重训之前必须先定死目标类别表，因为**一旦开始训练就不能再改**（改了要重来）。

### 2.1 方案 B1：合并为 5 类（推荐）

| 新编号 | 类别名 | 由哪些旧类别合并 | 说明 |
|---|---|---|---|
| 0 | hand-raising | 旧 0 | 举手 |
| 1 | focused-learning | 旧 1 + 旧 2 | 专注学习（阅读与写作合并） |
| 2 | using phone | 旧 3 | 使用手机 |
| 3 | bowing the head | 旧 4 | 低头 |
| 4 | leaning over the table | 旧 5 | 靠在桌上 |

**为什么推荐合并阅读与写作**：
- 两者都是「与学习任务相关的投入行为」，语义上同属专注，合并后专注度计算不必再分两项
- 两者标注形态相似（身体前倾、专注于桌面/书本），合并可**减少模型在两类间的混淆**，理论上能提升该大类整体精度
- 合并后该类实例达 13813 个（占 55.6%），是绝对主导类

**合并的代价**：失去了「这节课学生主要在读书还是在写字」的细分信息，报告中无法再区分阅读与写作的人数。

### 2.2 方案 B2：保持 6 类但重命名（更保守）

如果不希望丢失细分，只把含义含糊的类别改名，`nc` 仍为 6：

| 编号 | 新名 | 原名 | 改动 |
|---|---|---|---|
| 0 | hand-raising | hand-raising | 不变 |
| 1 | reading | reading | 不变 |
| 2 | writing | writing | 不变 |
| 3 | using phone | using phone | 不变 |
| 4 | bowing head | bowing the head | 不变 |
| 5 | lying on desk | leaning over the table | **改名**，语义收窄为「上身贴伏桌面」 |

> 注意：改名**只改 data.yaml，不改标注文件**（标注里存的是数字编号，编号不变即可）。这是最省力的操作。

### 2.3 关于「靠在桌上」的优化

你提到靠桌需要优化。这里有三种不同的「优化」，含义差别很大：

| 理解 | 具体做法 | 是否需要重训 |
|---|---|---|
| **语义/命名优化** | 把「靠在桌上」改名为更准确的「身体贴伏桌面 / 趴伏」，并在论文与界面统一表述 | **不需要**，改 `data.yaml` + `config.py` 文案 |
| **判定阈值优化** | 不改模型，在专注度层对该类权重调低/调高，或对检出框的宽高比、与桌面距离做后处理过滤 | **不需要**，改 `attention.py` / `detector.py` |
| **识别精度优化** | 该类现有实例仅 1085 个（4.4%），样本偏少导致精度受限；需增补样本或调整标注规范后重训 | **需要** |

**如果只是想让「靠桌」描述更准确、更贴合教学语境，建议只做前两项**，成本极低且无风险。第三项属于模型层面的功夫，收益不确定。

### 步骤 2：写标签合并脚本

在 `datasets/` 下新建 `merge_labels.py`：

```python
# -*- coding: utf-8 -*-
"""把阅读(1)与写作(2)合并为 focused-learning(1)，生成 5 类数据集。

YOLO 标注格式：每行 <class_id> <x_center> <y_center> <w> <h>
合并规则：旧 0->新 0，旧 1->新 1，旧 2->新 1，旧 3->新 2，旧 4->新 3，旧 5->新 4
"""
from pathlib import Path

SRC = Path("datasets/dataset_merged/labels")   # 就地修改副本
MAPPING = {0: 0, 1: 1, 2: 1, 3: 2, 4: 3, 5: 4}  # 旧编号 -> 新编号

def main() -> None:
    total_files = 0
    total_boxes = 0
    changed = 0
    for split in ("train", "val", "test"):
        folder = SRC / split
        if not folder.exists():
            continue
        for txt in folder.glob("*.txt"):
            lines_out = []
            for line in txt.read_text(encoding="utf-8").splitlines():
                parts = line.strip().split()
                if len(parts) < 5:
                    continue
                old_id = int(parts[0])
                new_id = MAPPING.get(old_id)
                if new_id is None:
                    continue          # 未知类别直接丢弃
                if old_id != new_id:
                    changed += 1
                lines_out.append(" ".join([str(new_id)] + parts[1:]))
                total_boxes += 1
            txt.write_text("\n".join(lines_out) + "\n", encoding="utf-8")
            total_files += 1
        print(f"{split}: {total_files} 文件累计")

    print(f"\n完成：改写 {total_files} 个标注文件，{total_boxes} 个目标框")
    print(f"其中 {changed} 个框的类别编号被修改（阅读/写作 -> 1）")

if __name__ == "__main__":
    main()
```

执行：

```powershell
.venv\Scripts\python.exe datasets\merge_labels.py
```

**预期输出**：改写 2032 个标注文件，约 35064 个目标框，其中约 19314 个框编号被改（阅读 14158 + 写作 5156）。

> **验证点**：执行前先记录 `reading` 与 `writing` 的实例数（14158 与 5156）。合并后新类别 1 的实例数应为 **19314**。若不等于此值，说明脚本有误，立即从 `datasets/dataset` 重新复制。

### 步骤 8：兼容历史数据（**这一步不做会导致报告报错**）

数据库 `detection_record.behavior_type` 里已经存了旧键名 `reading`、`writing`。改成 5 类后，历史课堂报告会查不到这两个键，导致图表缺项。

两种处理：

**方式一（推荐，保留历史可读）**：在统计层做兼容映射，不改数据库

在 `detection/behavior.py` 的汇总函数中加入旧键到新键的映射：

```python
# 历史数据兼容：旧键 reading/writing 归入 focused_learning
LEGACY_MAP = {"reading": "focused_learning", "writing": "focused_learning"}

def _normalize_key(key: str) -> str:
    return LEGACY_MAP.get(key, key)
```

对读取历史记录的地方统一套用该映射，即可让旧课堂报告在 5 类体系下正常展示。

**方式二**：写一次性 SQL 迁移，把历史记录改键

```sql
UPDATE detection_record SET behavior_type='focused_learning'
WHERE behavior_type IN ('reading','writing');
```

> 方式二更彻底，但**不可逆**（合并后无法再区分历史上哪些是阅读、哪些是写作）。若论文需要保留细分数据，选方式一。

## 四、原理说明

### 4.1 YOLOv8 里的「类别」到底是什么

YOLO 系列检测器把「类别」编码为一个整数标签。训练时，每个标注框携带一个 `class_id`；模型的检测头输出 `nc` 个通道的分类分数，取最大者为预测类别。

因此：
- `nc` **必须**等于 `names` 的实际条目数，且编号从 0 连续
- 类别编号与「名字」之间是**纯映射关系**，改名字不影响权重，改编号则等于换了任务
- **合并两个类别**，本质是把原本属于两个分类通道的样本全部归到一个通道，模型不再需要区分它们，该通道的样本量翻倍

### 4.2 合并为什么可能提升精度

原「阅读」与「写作」在视觉上高度相似（都是身体前倾、专注桌面）。模型原本要在两者间做细微区分：
- 区分成功 → 正确分类
- 区分失败 → 被判成「另一个类」，在 mAP 计算中算作**误检**（虽然框的位置是对的）

合并后，这类「位置正确但类别判错」的情况直接变成「判对」，因为两类已无差别。这就是合并能提升整体 mAP 的原因——它**消除了一个不可能完全解决的类间歧义**。

代价是丢失了信息粒度。这是**精度与粒度之间的权衡**，不是纯粹的改进。

### 4.3 「靠在桌上」为什么难识别

该类仅 1085 个训练实例（4.4%），且与「低头」在姿态上高度相似（都表现为身体前倾、头部偏低）。在混淆矩阵中这两类很容易互相误判。

要让「靠桌」更准，本质上有三条路：
1. **更多样本**（成本最高）
2. **更明确的标注规范**（例如规定「上身前倾角度超过 X 或与桌面接触」才算靠桌，减少标注歧义）
3. **引入额外线索**（如身躯与桌面的接触区域、姿态关键点）

仅改类别名或调权重，**不会提升识别精度**，只会改变展示文案或分数影响。这一点必须分清。

## 五、风险与建议

### 5.1 主要风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| **无 GPU 时训练耗时过长** | 250 轮可能需十几小时 | 先在 GPU 环境跑；或降到 50 轮验证流程通不通 |
| **合并后精度反而下降** | 不如原 6 类模型 | 步骤 5 设定验收门槛，不达标就不替换 |
| **漏改代码绑定** | 检测正常但统计/报告错乱 | 步骤 7 的 6 处逐一核对；步骤 9 跑回归测试 |
| **历史数据键名不兼容** | 旧课堂报告缺项或报错 | 步骤 8 做映射兼容 |
| **原始标注被误改** | 数据集损坏不可恢复 | 步骤 1 必须复制副本，只在副本上改 |
| **论文数据需全部重做** | 第 6 章的模型指标、权重实验结论全部失效 | 重训后需重新生成 `docs/模型评估指标.md`、重跑权重实验、更新论文第 6 章 |

> **最后一条尤其要注意**：一旦换了模型，论文第 6 章的报告 mAP、各类别精度、混淆矩阵图、甚至权重对比实验的样本数据都要重做。这不是改代码的成本，是**重做实验的成本**。

### 5.2 我的建议

如果目的是「**让系统的类别语义更贴合教学、并优化靠桌的表述**」，而不追求模型结构变化，建议**不做重训**，改走轻量路线：

1. **只做逻辑归类**：模型仍六类，在统计层提供「专注学习（阅读+写作）」的分组展示
2. **只改文案**：把「靠在桌上」在界面与论文中统一表述为「身体贴伏桌面（接近疲劳状态）」
3. **微调权重**：若认为靠桌应更严厉，把权重从 0.2 调整（属于可解释的参数设计，不需要重训）

这三项加起来**不超过一小时**，且不会推翻论文第 6 章的任何实验数据。

只有在下面这种情况下才值得重训：
- 你有 GPU 环境，训练不是瓶颈
- 你愿意重做第 6 章的全部实验数据
- 你确实需要模型只输出 5 类（例如为了进一步压缩模型或简化部署）

## 附录 C：30 秒确认权重里到底有几个类别

```powershell
.venv\Scripts\python.exe -c "from ultralytics import YOLO; m = YOLO('models/classroom_behavior.pt'); print('类别数:', len(m.names)); print(m.names)"
```

输出应为：

```
类别数: 6
{0: 'hand-raising', 1: 'reading', 2: 'writing', 3: 'using phone', 4: 'bowing the head', 5: 'leaning over the table'}
```

若输出中**没有** 「听课」相关条目，即证实 1.2 节的结论。
