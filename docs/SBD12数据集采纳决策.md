# SBD12 数据集评估结论与本项目采纳决策

> 本文档基于 `docs/SBD12数据集可用性评估.md`，并对其核心结论做了**独立复核实测**。
> 结论对既有方案（含已构建的 `datasets/sbd8/` 8 类方案）有实质性影响，请完整阅读。
> 复核日期：2026-11-06

---

## 一、最终结论

**这份数据集质量不错，但当前不能用于替换或合并训练本项目模型；已构建的 8 类方案同样不可直接接入。**

| 评估维度 | 判断 | 复核方式 |
|---|---|---|
| 场景匹配度 | ✅ 好 | 教室侧后方全景，640×640 |
| 数据规模 | ✅ 大 | 216098 个标注框（现有数据集 35064 框，约 6.2 倍） |
| **一个学生 = 两个框** | ❌ **致命冲突** | **实测抽样 300 张，97.3% 头部框中心落在身体框内** |
| **train 为 3 倍亮度副本** | ⚠️ **规模虚高** | **实测 4788 个标注文件仅有 1596 种内容，每种恰好 3 份** |
| 测试集缺类 | ❌ 严重 | hand-raising 与 writing 在 test 中均为 0 个实例 |
| 自带权重 | ❌ 不可用 | 仅训练 3 个 epoch，测试集 mAP@0.5 = 0.1878（本人实测） |
| 类别体系 | ❌ 含物体类 | `book`/`phone`/`Using_phone` 是物体框，会污染人数统计 |

**一句话**：这份数据集的标注是**分层的**（学生身体 + 头部状态 + 物体），而本项目的算法前提是「**1 个检测框 = 1 名学生**」。两者正面冲突，直接接入会让专注度分数**系统性偏高约一倍**。

## 二、复核实测记录（本文档与评估报告的差异说明）

原评估报告已给出较完整结论，但为避免误用，我对其中三条**最关键的结论**做了独立复核：

### 2.1 复核实测：train 是 3 倍亮度副本（证实）

对 `train/labels` 下 4788 个标注文件做内容哈希去重：

```
train 标注文件总数: 4788
不同标注内容数:     1596
重复组数:           1596
每个重复组份数分布: {3: 1596}   ← 每组恰好 3 份
```

**结论**：宣传语中的「5661 张图片」实际只有 **2469 个独立场景**（1596 + 581 + 292）。train 集是同一画面做了 3 份亮度变化的增强副本，标注完全相同。

**影响**：
- 数据量的心理预期要下调到 1/3
- 若按文件数划分 train/valid/test，会造成「同场景出现在不同集合」的**数据泄漏**
- 正确做法是按**独立场景**划分，而非按增强副本

### 2.2 复核实测：一人两框（证实，且比原报告更严重）

原报告称抽样 320 张图中 55.7% 的非 upright 框中心落在 upright 框内。我采用更严格的判据（**头部框中心落入任一体框**）：

```
抽样 300 张图
头部框总数: 4552
中心落在身体框内的头框: 4431 (97.3%)
```

**结论**：`bow_head`(低头)、`raise_head`(抬头)、`turn_head`(转头) 这三类**本质是"同一个学生的头部状态"**，而非独立目标。它们与身体框（upright/bend/sleep/reading/writing/hand-raising）构成**一对多的嵌套关系**。

**若直接按「框数 = 人数」统计，一名学生会被计为 2 人**：

| 场景 | 真实 | 现有公式计算结果 |
|---|---|---|
| 1 名学生低头 | 0.30（分母 1） | **0.65（分母 2）** ← 一名学生被算成两人 |
| 20 人全低头 | ≈30% | **≈65%** ← 分数翻倍 |

### 2.3 复核实测：我构建的 8 类方案也中招（关键）

这是**本次复核最重要的发现**，直接推翻了此前的工作成果。

`datasets/build_sbd8.py` 构建的 8 类方案，类别来源如下：

| 新编号 | 类别 | 来自 | 标注对象 |
|---|---|---|---|
| 0 | 听课 | upright (10) | **身体框** |
| 1 | 阅读 | reading (7) | **身体框** |
| 2 | 写作 | writing (11) | **身体框** |
| 3 | 举手 | hand-raising (4) | **身体框** |
| 4 | 使用手机 | Using_phone (0) | **物体框**（手机本身，非学生） |
| 5 | 低头 | bow_head (3) | **头部框** |
| 6 | 睡觉 | sleep (8) | **身体框** |
| 7 | 转头 | turn_head (9) | **头部框** |

**实测**：

```
sbd8 train 总图 3963
同时含身体框与头部框的图: 2454 (61.9%)
```

**结论**：8 类方案把**身体框与头部框混在同一检测任务里**，`低头`、`转头` 是头框，`听课`、`阅读` 等是身体框，同一学生在图里会同时产生「听课 + 低头」两个框。

于是：

- 专注度公式的语义前提（ΣN_i = 学生数）**被破坏**
- `低头` 权重 0.3 + `听课` 权重假设 1.0 → 一名低头学生被算成 1.3 人份
- 61.9% 的图片都存在这个冲突

**必须明确：8 类方案不是"稍加修改就能用"，而是在错误的标注口径上建的。**

## 三、为什么我此前的建议有误（如实说明）

在此前的对话中，我建议了「方案 A：8 类重训」，并已实际构建数据集、安装 CUDA、写好训练脚本。这个建议的基础有两处疏漏：

| 疏漏 | 后果 |
|---|---|
| 只看了 `data.yaml` 的类别名，**没有检查每个类别标注的是什么对象** | 把「头部状态」与「学生身体」当成同一层级的类别 |
| 只统计了框数分布，**没有做嵌套检验** | 没有发现 97.3% 的头框嵌在身体框里 |

这两点是评估课堂行为数据集的关键检查项，我漏掉了。原评估报告在这些方面做得比我的方案更严谨，**应以它的结论为准**。

**已产生的沉没成本**（均不影响项目主体功能，可保留）：
- `torch-2.5.1+cu121` 已装（GPU 可用，对后续任何训练都有益）
- `datasets/build_sbd8.py` 脚本（分层切分逻辑可复用）
- `training/train_sbd8.py` 脚本（训练参数可复用）
- `datasets/sbd8/` 数据集（**不建议直接训练，但可作为两阶段方案的原料**）

## 六、若后续走路线 C（两阶段方案），实施要点

### 6.1 架构

```
阶段 1（检测器）：只训身体类（upright / bend / sleep / reading / writing / hand-raising）
        → 输出每个学生的位置，N = 学生数（准确计数）

阶段 2（分类器）：对阶段 1 的每个框裁剪出小图
        → 分类为 低头 / 抬头 / 转头 / 使用手机 / 书写 / 阅读 / 听讲
        → 每人恰好 1 个状态
```

### 6.2 为什么这个架构能解决根本问题

| 当前缺陷 | 两阶段如何解决 |
|---|---|
| 框数 ≠ 人数（遮挡、漏检、嵌套头框） | 阶段 1 只输出身体框，**一个学生一个框** |
| 专注度分母不可信 | N 来自身体框计数，`ΣN_i = N` 语义成立 |
| 同一学生多框导致分数虚高 | 阶段 2 输出**每人体一个状态标签**，天然不重复 |
| 头部状态与身体姿态混淆 | 拆成两个任务，各自专精 |

### 6.3 具体步骤

1. **身体框筛选**：从 12 类中只保留 `upright/bend/sleep/reading/writing/hand-raising`，得到阶段 1 数据集
2. **按独立场景重划分**：使用 1596 个独立场景（不是 4788 个增强副本），7:1.5:1.5 分层
3. **训练阶段 1 检测器**：YOLOv8s，100 轮，目标 mAP@0.5 ≥ 0.85
4. **构建阶段 2 分类数据集**：对每个身体框裁剪，用嵌套在其中的头框/物体框确定状态标签
5. **训练阶段 2 分类器**：YOLOv8-cls 或轻量 CNN，输入 128×128 裁剪图
6. **改造系统代码**：`detection/detector.py` 增加两阶段调用，`attention.py` 的 `ΣN_i` 改为使用阶段 1 的 N
7. **回归测试 + 论文第 5、6 章重写**

### 6.4 已有可复用的资产

| 资产 | 复用方式 |
|---|---|
| `datasets/build_sbd8.py` | 分层切分逻辑（需补充"按场景去重"与"去嵌套"） |
| `training/train_sbd8.py` | 训练参数与资源保护配置 |
| CUDA 版 torch | 直接可用 |
| 8 类数据集 | 需按身体/头部拆分后重建，当前形态不可直接用 |

## 八、给答辩的一个建议

如果答辩时被问「为什么不使用更大的公开数据集／为什么只用 6 类」，可以这样回答：

> 我们评估过公开的 12 类课堂行为数据集，规模是现有数据的 6 倍。但调研发现它的标注是分层的——同一名学生同时有身体框和头部状态框，而我们的统计口径是一个框对应一名学生。直接接入会导致学生人数重复计数，专注度分数虚高近一倍。因此我们选择保持 6 类、口径一致的现有数据集，并把分层标注数据作为后续两阶段检测的方向。这说明我们在数据选型上做过实测论证，而不是简单地"数据越多越好"。

这个回答比「没做」或「直接用了」都更有说服力。

## 九、一句话总结

> **SBD12 数据集场景对、规模大、质量不差，但它的标注是分层的（身体 + 头部 + 物体），与本项目「一框一人」的算法前提正面冲突；已构建的 8 类方案因混用身体框与头部框（61.9% 的图存在此冲突）同样不可直接使用。答辩前建议保持现有 6 类模型不变，把这份数据集的调研结论写进论文，作为数据选型论证与后续两阶段架构的展望。**
